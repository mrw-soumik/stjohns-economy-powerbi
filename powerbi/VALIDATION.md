# How the Power BI project was validated

The Power BI Project in `powerbi/project/` was generated and checked on a Mac,
where Power BI Desktop cannot run. This page lists every automated check, the
tool and version used, the command, the result on 2026-10-18, and what can only
be confirmed in Power BI itself.

Everything under `powerbi/project/` is generated by `python -m stjohns_econ design`
from `powerbi/queries.pq`, `powerbi/measures.dax`, `powerbi/theme.json` and
`src/stjohns_econ/report_spec.py`, except one file:
`StJohnsEconomy.Report/StaticResources/SharedResources/BaseThemes/Fluent2-CY26SU08.json`,
the base theme Power BI Desktop saved in August to October 2026, copied from
Microsoft's MIT-licensed `fabric-toolbox` sample.

## Commands

```bash
# 1. PBIP and PBIR JSON (part of the test suite)
python -I tools/pbip-validate/validate_pbip.py --strict powerbi/project

# 2. TMDL. One-time setup of a .NET SDK inside tools/tmdl-validator (nothing system-wide).
#    Use the osx-x64 file on an Intel Mac; Microsoft publishes the SHA-512 for each file
#    in https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json
cd tools/tmdl-validator
curl -LO https://builds.dotnet.microsoft.com/dotnet/Sdk/10.0.402/dotnet-sdk-10.0.402-osx-arm64.tar.gz
shasum -a 512 dotnet-sdk-10.0.402-osx-arm64.tar.gz      # compare with the published hash
mkdir dotnet && tar -xzf dotnet-sdk-10.0.402-osx-arm64.tar.gz -C dotnet
. ./env.sh && dotnet publish src/TmdlValidator -c Release -o bin
./tmdl-validate.sh ../../powerbi/project/StJohnsEconomy.SemanticModel --strict --roundtrip /tmp/tmdl-roundtrip
cd ../..

# 3. Everything else, including steps 1 and 2 when the TMDL validator is built
python -m pytest
```

`env.sh` keeps the SDK, NuGet packages and CLI state inside `tools/tmdl-validator`
(all git-ignored). The validator exits with 0 when the model is valid and 1 when
it finds errors.

## What only Power BI can confirm

These were designed from Microsoft's schemas and from files that Power BI Desktop
itself saved, but they could not be run on a Mac:

1. **Opening the project.** The schema versions match what Power BI Desktop wrote
   in September 2026 (visualContainer 2.13.0, report 3.3.0); a newer Desktop may
   upgrade files when it saves.
2. **DAX evaluation.** The measures are syntax-checked and their logic is
   mirrored and tested twice, but the Power BI engine has not run them. Run the
   check query at the end of `measures.dax` in DAX query view and compare it
   with `check-query-expected.csv`.
3. **Power Query evaluation.** `Web.Contents` against `raw.githubusercontent.com`,
   the type conversions with the `en-CA` culture, and the anonymous credential
   and Public privacy level.
4. **Rendering.** Card sizes and the change label placed under each value, legend
   and label placement, series colours applied through selectors, line-end
   series labels, the three slicer styles and their synchronisation across pages,
   the page-level date filter, the "no filter" interactions from the geography
   slicer, keyboard tab order and screen-reader output.
5. **Theme application.** The theme validates, but Desktop decides how it
   combines with the base theme.
6. **Service behaviour.** Credentials, refresh and "Publish to web" (see
   `docs/publish-guide.md`).

If something renders differently in Desktop, fix it in `report_spec.py` or
`pbip.py` (not in the generated files), run `python -m stjohns_econ design` and
`python -m pytest`, and commit both the change and the regenerated project.
